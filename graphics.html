The question

In real time, a result is only as good as the frame it arrives in. A model that is faster in a benchmark can be slower in a renderer, and a cache that saves work on one GPU can cost more on another.

So I ask graphics the same question I ask robots: does what holds offline still hold at sixty frames per second, on the hardware people actually use? The figure above is a small version of it. Offline, the image converges. In real time, every frame gets one sample per pixel, and the trade-off shows up as noise and ghosting, traced on your own GPU a moment ago.

G2

Neural frame interpolation

When faster isn't faster

A frame-interpolation network embedded in a Direct3D 12 render loop, with frames shared between D3D12 and CUDA without copies. The back end that was faster in isolation turned out slower in the pipeline: a model's speed belongs to the system it runs in.

  • NSTC-funded
  • D3D12 · CUDA
  • Inference back ends
G3

Neural Radiance Caching

A network that trains every frame

In NVIDIA's open-source RTXGI, a small network is trained and queried while the renderer runs. I removed a GPU-wide serialization on the desktop, then ported the full training loop to a phone GPU and measured where it does not yet pay off.

  • Open-source RTXGI
  • Vulkan · SPIR-V
  • On-device training
